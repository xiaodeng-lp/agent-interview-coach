# Project State

## Current Goal

Agent Interview Coach is a local-first AI mock interview coach for AI/Agent roles.
It reads resume and project materials, builds interview context, and conducts staged mock interviews through WeChat or CLI.

The current focus is:

- keep the WeChat bot stable and usable on mobile
- make the interviewer dynamic instead of a fixed question bank
- keep long-session token cost under control
- keep retrieval grounded in the strongest resume/project evidence
- preserve local-first privacy boundaries

## What Is Already Done

- WeChat bot is connected through `wechat-clawbot`.
- Local material import is working.
- Corpus cache is built from local files in `app/resume_materials`.
- Dynamic staged interview flow is implemented.
- Session memory, scoring, weaknesses, review, and answer bank are implemented.
- Token-saving improvements were added:
  - smaller context window
  - fewer retrieved chunks
  - shorter stored history
  - less repetition of protocol-like material in retrieval
- M0 evidence grounding was added:
  - retrieval context is rendered as a numbered `【本轮证据包】`
  - empty retrieval clearly says no relevant evidence was found
  - prompt assembly includes hard rules for evidence use
  - candidate experience, responsibilities, technical actions, metrics, and results must come from the current evidence pack or the user's current-turn supplement
  - model common sense is limited to concept explanation and expression polishing, not invented candidate experience
- M1-A session history hygiene was added:
  - raw provider response objects and traceback/error dumps are replaced with short placeholders before entering long-term history
  - invalid history items are dropped on load/save
  - long history messages are compacted before reuse
- M1-B mode-aware history selection was added:
  - prompt assembly preserves user messages but omits obvious assistant history that conflicts with the current mode
  - coaching mode omits old scoring-template assistant replies
  - technical interview modes omit old coaching/recovery teaching templates
  - selected history still respects `MAX_HISTORY_MESSAGES`
- M1-C weakness prompt budgeting was added:
  - `format_weaknesses(session)` keeps its default top-10 behavior for existing review/status uses
  - prompt assembly passes `max_items=5`, so only the top 5 accumulated weaknesses enter each model turn
  - full `session.weaknesses` data is preserved and is not trimmed during prompt rendering
  - `MAX_HISTORY_MESSAGES` remains at the current default while M1-B filtering continues to run
- M2-Prep retrieval diagnostics were added:
  - `app/interview_corpus.py --debug-query "..."` prints a local retrieval trace
  - diagnostics include selected/skipped state, chunk title/source, chunk index, priority, score, matched terms, and scoring reason
  - diagnostics include a final evidence pack preview generated by the same `select_context()` path used at runtime
  - no BM25, embeddings, new dependencies, or WeChat loop changes were introduced
- Chinese text repair pass was run:
  - UTF-8 file decoding passed for app and docs files
  - key runtime user-facing prompts in `app/commands.py`, `app/engine.py`, `app/cli_chat.py`, and `app/interview_corpus.py` were confirmed as real UTF-8 Chinese, not mojibake
  - remaining English open-question sections in key design docs were localized to Chinese
  - PowerShell `Get-Content` may still display Chinese incorrectly if the terminal encoding is not UTF-8
- Corpus cleanup rules were added:
  - skip temp files
  - skip backup / before / noisy resume variants
  - prefer the strongest core resume file
- Runtime safety improvements were added:
  - bot process scripts handle stale PID files
  - session JSON writes are atomic
  - corrupt session files are backed up and ignored safely
  - corpus cache writes are atomic
  - corrupt or source-mismatched corpus caches are rebuilt
  - WeChat startup backlog messages are skipped by default to prevent reply bursts
  - WeChat send calls have a timeout
- Two user-friendly mode aliases are available:
  - `/模式 面试`
  - `/模式 讲解`
- Coaching recovery behavior was added:
  - natural language requests like `你切教学模式` switch to coaching mode
  - user replies like `不会` / `不知道` / `答不上来` trigger a recovery explanation for that turn
  - uncertainty is recorded as the weakness `答不上来/概念不清`

## Known Issues

- Some terminal output may still look garbled on Windows if PowerShell is not in a UTF-8 session; current file content should be verified with UTF-8-aware Python or the mojibake scanner before editing.
- Bot process scripts were hardened for stale `coach_bot.pid`; older manually-started bot processes may still need manual cleanup if their command line lacks the absolute `coach_bot.py` path.
- The material corpus is cleaner now, but retrieval is still heuristic, not full RAG.
- Evidence-pack grounding is stricter now, and retrieval can now be diagnosed locally with `python app/interview_corpus.py --debug-query "..."`; recall is still heuristic and may miss relevant material.
- Mode-aware history filtering and weakness budgeting are heuristic; they reduce obvious prompt noise but do not yet provide a rolling summary.
- WeChat startup backlog skipping still needs one live validation with queued messages.
- Responses API style needs a future provider-shape recheck before being used again; keep `MODEL_API_STYLE=chat` unless `python smoke_test.py --model` passes cleanly with responses.
- The interviewer experience still needs live WeChat validation for the new coaching recovery flow.

## Token-Saving Rules For Future Sessions

1. Ask Codex to read this file first:
   - `请先读 docs/PROJECT_STATE.md 和 AGENTS.md，再继续这轮任务。`
2. Keep each conversation focused on one task only:
   - bot diagnosis
   - README rewrite
   - retrieval improvements
   - interview behavior
   - docs readability repair
3. Avoid pasting large logs or long file contents unless necessary.
4. Prefer asking Codex to inspect files directly instead of pasting them into chat.
5. If the topic changes, start a new thread instead of continuing a long mixed conversation.
6. If the conversation gets long, ask for a short checkpoint summary before moving on.
